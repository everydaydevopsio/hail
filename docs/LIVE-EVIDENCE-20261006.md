## Findings and fixes

The pinned AWS provider read S3 bucket configuration, SNS subscription attributes, Lambda function versions/code-signing, SES receipt-rule attributes, and CloudWatch/Lambda tags during provisioning. The initial bootstrap policy omitted several reads or used an ARN shape those APIs did not authorize. Terraform stopped on `AccessDenied` before activation; each correction was reviewed as a bounded change to the run provisioner/indexer policy, validated by Access Analyzer, and followed by positive provisioning. During teardown, `DeleteEventSourceMapping` succeeded but Terraform's polling `GetEventSourceMapping` was authorized against `*` after the mapping disappeared. A regional, read-only statement corrected this; resumed Terraform destroy completed. The accompanying mock policy assertions guard these provider requirements.

The live test harness now includes a packed-consumer magic-link and invitation test, a reproducible consumer preparation command, and a guarded object/version purge. The Bubblewrap runner used for this run is committed for repeatability. The parent Codex session still had access to the source profile; subprocess isolation does not constrain the parent agent.
